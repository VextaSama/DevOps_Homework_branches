## Задание 1
Опишите основные преимущества использования масштабирования методами:

активный master-сервер и пассивный репликационный slave-сервер;
master-сервер и несколько slave-серверов;
Дайте ответ в свободной форме.

В первом методе активный мастер сервер принимает запросы на чтение, изменение и запись, в то время как пассивный слейв сервер получает копию за счёт репликации.
Преимуществами такого полхода являются:
-Отказоусточивость, т.к. в случае выхода из строя изначального мастер сервера, можно слейв сервер повысить до роли мастера.
-Всегда актуальная условно резервная копия. Помимо полноценной резервной копии, расположенной где-то отдельно, у нас всегда будет в наличии актуальная резервная копия на слейв сервере. В каких-то отдельных случаях это может пригодиться.
Минусом такого подхода является то, что вся нагрузка лежит на мастер сервере.

Во втором методе на мастер сервере происходит запись, изменение, а несколько слейв серверов получают данные через реплекацию. Эти же слейв серверы можно использовать для операций чтения.
Преимуществами такого подходя являются:
-Разделение нагрузки. Пока мастер занимается записью, слейв серверы распределяют между собой запросы на чтение.
-Отказоустойчивость. При выходе из строя одного слейв сервера, нагрузка распределяется по оставшимся. При выходе из строя мастер сервера, один из слейв серверов можно назначить новым мастером.
-Масштабирование. При росте нагрузки по операциям чтения, можно добавлять новые слейв серверы без полной перестройки архитектуры.
Минус у этого подхода так же имеется. Мастер сервер здесь один, а значит масштабирование для операций записи ограничено.

## Задание 2
Разработайте план для выполнения горизонтального и вертикального шаринга базы данных. База данных состоит из трёх таблиц:

пользователи,
книги,
магазины (столбцы произвольно).
Опишите принципы построения системы и их разграничение или разбивку между базами данных.

Изначально имеется общая база данных, в которой находятся 3 таблицы. Users, Books, Shops. Для масштабирования используем комбинированный подход:
Вертикальный шаринг, горизонтальный шардинг и репликация мастер-слейв.
Вертикальный шардинг используем для Users и Books. Users делим на таблицу с частоиспользуемой информацией и на таблицу с более подробными данными.
Books делим по такому же принципу.
Таблица Shops вертикально не делится, т.к. считается менее объёмной.
Таким образом, мы делим данные по смыслу и снижаем нагрузку на базу данных.

Горизонтальным шардингом мы делим таблицы Users_profile и Books_name. Таким образом часто используемые данные, которые при этом весьма объёмные, будут распределены по диапазонам записей, чтобы равномерно распределить нагрузку.

Режимы работы серверов: Осовные сервера работают в режиме Мастер.

Users_profile Master 1
Users_profile Master 2
Users_detail Master

Books_name Master 1
Books_name Master 2
Books_details Master

Shops Master-Server

Они принимают операции по записи, изменению, удалению. Для части мастер-серверов создаются слейв-сервера, работающие в режиме read only. На схеме:

Users_profile Master 1 → Users_profile Slave 1
Users_profile Master 2 → Users_profile Slave 2

Books_name Master 1 → Books_name Slave 1
Books_name Master 2 → Books_name Slave 2

Shops Master-Server → Shops Slave

Слейв серверы получают данные со своих мастер-серверов и используются для чтения, отчётов и резервного копирования.

Пришлите блоксхему, где и что будет располагаться. Опишите, в каких режимах будут работать сервера.
